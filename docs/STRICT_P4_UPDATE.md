# v1.2.0：严格P4与重排分析

## 当前判定

P4为“未发现敌方并超时”的预定义关键业务路径。除M0、M1、M8阶段匹配及timeout终局要求外，还要求全部`state_flags`（包括终止步）均不含M2。终局M8的阶段优先级可能遮盖同一步的M2标记，因此原阶段序列判定器不足以独立检查此条件。

`scripts/replay_experiment.py`的`strict_replay_paths`补上该约束，`evaluate_episode`用于存档复核和新执行结果。缺少逐步标记或序列长度不一致时拒绝判定，不把缺失数据视为未发现敌方。P1、P2、P3、P5的定义、变体、守卫与允许绕行不变。

## 结果对应

在24180条唯一回合中，历史判定记为P4的4581条中，有125条在终止步出现M2，严格判定保留4456条。125条回合在最终设计中被引用278次（随机4、参数组合21、本文56、奖励197）；这些引用在原顺序中均已有更早的有效P4覆盖，故全部1200条累计覆盖曲线、表5、首次全覆盖位置及12项统计检验不变。

改变分析顺序后，部分失效P4引用会出现在有效P4之前，因此重排AUC略有变化。当前结果为：

| 方法 | 严格P4重排KPC-AUC | 四位小数 |
|---|---:|---:|
| 随机设计 | 0.7127693333333334 | 0.7128 |
| 参数组合设计 | 0.6890584444444444 | 0.6891 |
| 历史奖励引导 | 0.335674 | 0.3357 |
| 本文方法 | 0.8985631111111111 | 0.8986 |

原冻结顺序下本文KPC-AUC仍为0.9403。原顺序与重排均值的差异来自分析顺序，不是两个相互矛盾的主实验结果。旧版本数值留在旧标签，不与当前结果混列为论文结论。

## 公开文件与复核

- `data/reordering_plan.json`：100种相同位置排列、零基标志、原生成种子及生成器。
- `results/p4_corrections.json`：125条修正记录的标识、原轨迹SHA-256、M2出现位置和修正前后路径集合。
- `results/reordering_summary.json`：四方法精确分数、各排列均值、整数累计路径数。
- `results/record_verification.json`：记录、组合与统计复核报告。

运行`python scripts/replay_experiment.py verify-records`，会从原始压缩状态记录重新计算并核对上述修正清单和重排汇总，不直接读取修正清单替代判定。该命令只复核既有执行记录，不进行仿真。原始观测未完整保存，复核范围是状态标记和阶段序列到覆盖的计算。

模型、历史输入及冻结计划保持原样，以避免评价修正反向影响设计。`verify-design`继续基于已公开的2352回合统计输入重建设计，无需重跑标定。正式重跑入口对新执行结果使用相同的严格P4规则，并与经严格复核的存档比较。

## 论文数据声明对应

论文“代码、模型、用例及实验记录见公开仓库，支持结果复核与正式实验重跑”对应本仓库v1.2.0。表5、覆盖曲线和统计检验由`reproduce.py`复算；逐例覆盖与重排AUC由`verify-records`复核；加载模型执行冻结计划由`rerun`完成。各入口实际验证范围见`RELEASE_VALIDATION.md`。
